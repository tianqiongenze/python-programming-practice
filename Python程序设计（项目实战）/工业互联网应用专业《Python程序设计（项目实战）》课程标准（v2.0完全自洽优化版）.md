### 1.2 课程定位与创新特点

《Python程序设计（项目实战）》是一门**完全自包含的独立工程应用课程**，特别为已掌握C语言基础的大二学生设计。

**四大核心定位**：

1. **从C到Python的自然过渡**
   - 完全跳过基础语法讲解阶段
   - 利用C语言逻辑思维加速学习
   - 第1-2周集中补充Python特有概念（OOP、列表/字典等）
   - 第3-9周直接进入工程实战

2. **融合式教学**（不是串联式）
   - 不是"先学Python→再学数据处理→再学ML"的三部曲
   - 而是"在做数据采集项目中学网络编程、在做故障诊断中学机器学习"
   - 知识点按需补充，即学即用

3. **对标企业岗位**
   - 每个项目都来自真实工业互联网场景
   - 代码规范遵循企业标准（PEP 8）
   - 强调可维护、可测试、可部署的工程能力
   - 毕业后可直接胜任数据工程师、AI应用工程师等岗位

4. **时间高效利用**
   - 仅8周（32课时）完成5大核心能力训练
   - 或扩展到9周（36课时）增加综合项目实战
   - 学习效率相比大一基础课提升3-4倍

### 1.5 课程设计理念

**五大教学原则**：

1. **自包含原则** — 完全不依赖其他课程
   - 所有必要的Python基础都在第1-2周讲解
   - 数据科学、机器学习基础在应用时即时补充
   - 学生可随时中断，仍能完成前期工单

2. **项目驱动原则** — 真实问题激发学习
   - 每个模块围绕一个真实工业场景
   - 工单难度与现实应用对标
   - 学生在解决"真问题"中自然学习技术

3. **渐进式补充原则** — 知识按需推送
   - 第1-2周：C→Python的基础转换
   - 第3-9周：每周补充该周需要的新知识（穿插在讲义中）
   - 避免在一周内有3-4个陡峭的新概念

4. **工程实践原则** — 企业级代码规范
   - PEP 8代码规范循序渐进（第3周70% → 第8周90%）
   - 引入Git版本控制、单元测试、代码审查
   - 强调代码可维护性和测试覆盖率

5. **激励创新原则** — 鼓励个性化学习
   - 工单有"及格"和"优秀"两个目标，无强制封顶
   - 第9周综合项目鼓励学生选择感兴趣的方向
   - 超出预期的创新给予加分

##### **任务P2.2：NumPy特征工程（⭐⭐⭐⭐）**

**知识补充**：
- NumPy数组基础：ndarray、dtype、shape、reshape
- 数组操作：索引、切片、迭代、形状变换
- 向量化计算：性能与纯Python对比（100倍提速演示）
- 广播机制（broadcasting）
- 线性代数：矩阵乘法、求逆、特征值分解、QR分解
- 统计计算：均值、方差、相关系数、协方差矩阵
- 傅里叶变换（FFT）与频域分析
- **特征提取实战**：
  - 时域特征（10个）：均值、标准差、峰值、峰值-谷值、斜度、峰度、能量、RMS、脉冲指标、边际指标
  - 频域特征（15个）：主频率、频率带宽、能量分布、频域质心、频域方差等
  - 统计特征（5个）：偏度、峰度、变异系数、信息熵

**工业场景**：
振动传感器数据的故障特征提取（设备状态监测）

**工单P2.2**：完整的设备故障特征提取系统

**输入数据**：
- 振动传感器时间序列（100Hz采样，10秒片段，1000个点）
- 100-500个样本

**特征提取要求**：
- 时域特征：10个
- 频域特征：15个（需要FFT分析）
- 统计特征：5个
- **总计30个特征维度**

**核心实现要点**：
1. 使用NumPy向量化计算（禁止循环）
2. FFT计算频域特征
   ```python
   from numpy.fft import fft
   spectrum = np.abs(fft(signal))
   freqs = np.fft.fftfreq(len(signal), 1/100)  # 100Hz采样率
   ```
3. 特征标准化（Z-score或Min-Max）
4. 特征矩阵形状：(N_samples, 30)

**性能指标**：
- 特征完整性：100%（30个特征全部计算）
- 计算效率：< 100ms处理1000个样本（10 samples/sec）
- 数值稳定性：处理信号范围1e-6 ~ 1e6都能正确计算

**输出格式**：

## 24. nbgrader 原生作业系统 (v2.4 新增)

### 概述

JupyterHub 已安装 **nbgrader 0.9.5**，提供原生的作业分发、收集、自动评分和反馈功能，替代了之前的手动 code_grader.py。

### 教师操作流程

```bash
cd ~/work/nbgrader

# 1. 创建作业（在 source/ 目录下创建 Notebook）
#    在 JupyterLab 中使用 nbgrader 工具栏标记单元格类型:
#    - 答案区（Solution）: 学生需要填写的代码
#    - 测试区（Test）: assert 断言（自动评分用）
#    - 只读区（Read-only）: 题目描述

# 2. 生成学生版（自动去除解决方案）
python3 -m nbgrader generate_assignment ps1

# 3. 发布作业到 exchange
python3 -m nbgrader release_assignment ps1

# 4. 查看已发布的作业
python3 -m nbgrader list

# 5. 学生提交后，自动评分
python3 -m nbgrader autograde ps1

# 6. 生成反馈
python3 -m nbgrader generate_feedback ps1
python3 -m nbgrader release_feedback ps1

# 7. 导出成绩 CSV
python3 -m nbgrader export
```

### 学生操作流程

```bash
cd ~/work/nbgrader

# 1. 查看可用作业
python3 -m nbgrader list

# 2. 获取作业
python3 -m nbgrader fetch ps1

# 3. 完成作业后提交
python3 -m nbgrader submit ps1
```

### nbgrader 元数据要求

每个 nbgrader 单元格需要完整的 v3 元数据:
- `grade`: True/False（是否评分）
- `solution`: True/False（是否答案区）
- `task`: False
- `locked`: True/False（是否锁定）
- `points`: 浮点数（分值）
- `grade_id`: 唯一标识符
- `schema_version`: 3
- `cell_type`: "code"

### Exchange 目录

| 路径 | 说明 |
|------|------|
| `~/work/nbgrader/exchange/` | 共享交换目录 |
| `exchange/default/outbound/` | 教师发布的作业 |
| `exchange/default/inbound/` | 学生提交的作业 |
